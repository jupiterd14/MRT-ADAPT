🛠️ MRT-3 Debugging Guide

Complete error handling & syntax reference

🤖 Model & Prediction Errors ▼
ERR-MOD-001 Predictions are too low (7% instead of 27%)
❌ Cause: Feature scaler not being used correctly. Manual normalization instead of saved scaler.
✅ Solution: Use saved feature scaler from training:
# In feature_engineering.py
scaler_path = f'models_2022-2024_v5/{station}_{direction}_feature_scaler.pkl'
with open(scaler_path, 'rb') as f:
    feature_scaler = pickle.load(f)
features = feature_scaler.transform(features)
ERR-MOD-002 Target scaler not found / None
❌ Cause: Target scaler file missing or wrong path. Model output in 0-1 range but not converted.
✅ Solution: Load target scaler and inverse transform:
target_scaler = directional_scalers.get(f'{model_key}_target')
if target_scaler:
    prediction = target_scaler.inverse_transform(pred_scaled.reshape(-1,1))[0][0]
else:
    prediction = pred_scaled[0][0] * 100 # fallback
ERR-MOD-003 get_feature_sequence_for_station returns None
❌ Cause: Not enough historical data (need 24+ hours before target time).
✅ Solution: Ensure target date has at least 24 hours of history. For early 2025 data, use dates after Jan 5, 2025.
ERR-MOD-004 Feature sequence has huge values (1140+)
❌ Cause: Congestion column not normalized correctly. 'minutes_until_closing' column has raw minutes (0-1110).
✅ Solution: Normalize columns with values > 1:
for col_idx in range(features.shape[1]):
    col_min, col_max = features[:,col_idx].min(), features[:,col_idx].max()
    if col_max > 1.0:
        features[:,col_idx] = (features[:,col_idx] - col_min) / (col_max - col_min)
ERR-MOD-005 Model key not in directional_models
❌ Cause: Station name or direction spelling mismatch (e.g., 'North AVe' vs 'North Ave').
✅ Solution: Use exact station names: North Ave, Quezon Ave, Kamuning, Cubao, Santolan, Ortigas, Shaw Blvd, Boni Ave, Guadalupe, Buendia, Ayala Ave, Magallanes, Taft. Directions: 'Northbound' or 'Southbound' (capitalized).
🐍 Flask / Python Errors ▼
ERR-FLK-001 500 Internal Server Error
❌ Cause: Exception in route handler. Common: CSV reading error, missing file, type conversion issue.
✅ Solution: Add try/except with traceback:
try:
    # your code
except Exception as e:
    import traceback
    traceback.print_exc()
    return jsonify({'error': str(e)}), 500
ERR-FLK-002 Circular Import Error
❌ Cause: Module A imports B, B imports A. Common between predictor.py and model_loader.py.
✅ Solution: Move shared imports to __init__.py or import inside functions:
def get_directional_prediction(...):
    from services.model_loader import directional_models
    # use it here
ERR-FLK-003 Duplicate route / View function mapping overwriting
❌ Cause: Same route decorated twice in different places.
✅ Solution: Search for duplicate function names. Keep only one definition per route.
ERR-FLK-004 Object of type bool_ is not JSON serializable
❌ Cause: NumPy boolean types (np.bool_) in response data.
✅ Solution: Convert numpy types to Python natives:
def convert_numpy(obj):
    if hasattr(obj, 'item'): return obj.item()
    return obj
result = convert_numpy(result)
ERR-FLK-005 404 - Blueprint route not found
❌ Cause: Blueprint not registered or wrong URL prefix.
✅ Solution: Register blueprint in app.py:
from routes.api_model_performance import model_perf_bp
app.register_blueprint(model_perf_bp, url_prefix='/api')
📜 JavaScript Errors ▼
ERR-JS-001 fetch() failed / Network error
❌ Cause: Flask server not running, wrong URL, or CORS issue.
✅ Solution: Check Flask is running (python app.py). Use relative URLs like '/api/...' not 'localhost:5000/...'. Add error handling:
fetch(url).catch(error => {
    console.error('Fetch failed:', error);
    showToast('❌', 'Server not responding');
});
ERR-JS-002 xxx is not a function / undefined
❌ Cause: Function not defined in script, or called before DOM loaded.
✅ Solution: Wrap in DOMContentLoaded, or declare functions globally:
document.addEventListener('DOMContentLoaded', function() {
    // your initialization code
});
ERR-JS-003 Chart.js error - Chart is not defined
❌ Cause: Chart.js CDN not loaded, or Chart variable not available.
✅ Solution: Ensure Chart.js script tag is in head:
<script src="https://cdn.jsdelivr.net/npm/chart.js@4.4.0/dist/chart.umd.min.js"></script>
ERR-JS-004 Cannot read property '...' of null
❌ Cause: Element ID doesn't exist in DOM when script runs.
✅ Solution: Check element exists, or use optional chaining:
const el = document.getElementById('myId');
if (el) { el.innerHTML = 'value'; }
ERR-JS-005 Await is only valid in async function
❌ Cause: Using 'await' outside an async function.
✅ Solution: Add 'async' to function declaration:
async function loadData() {
    const response = await fetch('/api/data');
}
🗄️ Database & CSV Errors ▼
ERR-DB-001 CSV column has strings instead of numbers
❌ Cause: When writing CSV, numbers were saved as strings ('8.3' instead of 8.3).
✅ Solution: Convert on read or fix at write time:
# On read:
df['predicted'] = pd.to_numeric(df['predicted'], errors='coerce')

# On write (ensure numbers, not strings):
results.append({'predicted': float(round(value, 1))})
ERR-DB-002 MySQL connection refused
❌ Cause: MySQL server not running, wrong credentials, or wrong host/port.
✅ Solution: Check MySQL service is running. Verify DATABASE_URL in .env:
DATABASE_URL=mysql+pymysql://user:password@localhost:3306/dbname
ERR-DB-003 Table doesn't exist (1146)
❌ Cause: Database tables not created yet.
✅ Solution: Run migrations or create tables:
from app import app, db
with app.app_context():
    db.create_all()
ERR-DB-004 IntegrityError / Foreign key constraint fails
❌ Cause: Referencing a record that doesn't exist (e.g., user_id in report doesn't match any user).
✅ Solution: Ensure referenced record exists before creating relationship, or use db.session.rollback().
ERR-DB-005 FileNotFoundError: 2025.csv
❌ Cause: CSV file not in expected location.
✅ Solution: Check multiple paths:
possible_paths = [
    'data (2022-2024)/2025.csv',
    '../data (2022-2024)/2025.csv',
    '2025.csv'
]

⚠️ Critical Loopholes & Gotchas
┌─────────────────────────────────────────────────────────────────────────────┐ │ 1. DATA LEAKAGE - Most Common Mistake! │ │ ❌ WRONG: Scaling the entire dataset before splitting │ │ ✅ CORRECT: Fit scaler ONLY on training data, then transform validation │ │ │ │ 2. TEMPORAL ORDER │ │ ❌ WRONG: Random shuffle for train/val split │ │ ✅ CORRECT: First 80% of time = train, last 20% = val (no shuffle) │ │ │ │ 3. DIRECTION MISMATCH │ │ ❌ WRONG: Using same filtering for all stations │ │ ✅ CORRECT: Northbound = EXITS, Southbound = ENTRIES │ │ ⚠️ Terminals (North Ave, Taft) need special handling! │ │ │ │ 4. CONGESTION CALCULATION │ │ ❌ WRONG: Using global max across all stations │ │ ✅ CORRECT: Per-direction max (99th percentile of that station/direction) │ │ │ │ 5. MISSING FEATURES IN INFERENCE │ │ ❌ WRONG: Adding features that weren't in training │ │ ✅ CORRECT: Use EXACT same FEATURE_COLS list during prediction │ │ │ │ 6. SCALER PERSISTENCE │ │ ❌ WRONG: Recreating scaler during prediction │ │ ✅ CORRECT: Save and load the SAME scaler used in training │ │ │ │ 7. SEQUENCE BOUNDARIES │ │ ❌ WRONG: Allowing prediction with less than 24h history │ │ ✅ CORRECT: Only predict if idx >= SEQ_LENGTH │ │ │ │ 8. OPERATING HOURS │ │ ❌ WRONG: Predicting when MRT is closed (before 4:30 AM, after 10:30 PM) │ │ ✅ CORRECT: Return 0% or handle separately │ │ │ │ 9. VERSION MISMATCH WARNINGS │ │ ⚠️ "InconsistentVersionWarning: Trying to unpickle estimator from v1.6.1"│ │ → Normal warning, doesn't affect predictions. Can safely ignore. │ │ │ │ 10. 🧪 Testing & Validation Guide - How Accuracy is Measured ▼
📊 Testing Flow Overview
┌─────────────────────────────────────────────────────────────────────────────┐ │ HOW MODEL ACCURACY IS TESTED │ └─────────────────────────────────────────────────────────────────────────────┘ ┌─────────────────────────────────────────────────────────────────────────────┐ │ STEP 1: Load 2025 Data (NEW unseen data, not used in training) │ │ • 2025.csv contains actual passenger counts from Jan-Dec 2025 │ │ • This is data the model has NEVER seen before │ │ • Tests how well the model generalizes to new data │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ STEP 2: For Each Station × Direction (26 combinations) │ │ • Filter data correctly (Northbound = EXITS, Southbound = ENTRIES) │ │ • Aggregate by hour │ │ • Calculate ACTUAL congestion using training max (not 2025 max) │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ STEP 3: Select Random Test Dates │ │ • Only dates with 24+ hours of history (after Jan 5, 2025) │ │ • Randomly sample up to 10 dates per station/direction │ │ • Ensures unbiased test coverage │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ STEP 4: Generate PREDICTED Congestion │ │ • Call get_directional_prediction() with same logic as live system │ │ • Builds 24-hour feature sequence │ │ • Uses saved feature scaler and target scaler │ │ • Model outputs predicted congestion % │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ STEP 5: Compare & Calculate Error │ │ • Absolute Error = |Predicted - Actual| │ │ • Percentage Error = (Abs Error / Actual) × 100 │ │ • Verdict = EXCELLENT (<5%), GOOD (<10%), OKAY (<15%), NEEDS IMPROVEMENT │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ STEP 6: Save Results & Update Dashboard │ │ • Save to test_results/{station}_{direction}_results.csv │ │ • Update metrics cards (MAE, MAPE, test samples) │ │ • Update prediction vs actual chart │ └─────────────────────────────────────────────────────────────────────────────┘

📅 Why Test on 2025 Data?
┌─────────────────────────────────────────────────────────────────────────────┐ │ TRAINING DATA (2022-2024) │ TESTING DATA (2025) │ ├───────────────────────────────┼─────────────────────────────────────────────┤ │ Used to train LSTM models │ NEVER seen by model during training │ │ ~3 million rows │ ~1 million rows │ │ Contains patterns from past │ Tests if model GENERALIZES to new data │ │ │ │ │ Purpose: Learn relationships │ Purpose: Validate accuracy on future data │ │ between time, station, flow │ If model works on 2025 data, it's READY │ │ and congestion │ for real-time predictions │ └───────────────────────────────┴─────────────────────────────────────────────┘ ⚠️ IMPORTANT: Training max values (per_direction_max_passengers.pkl) are calculated from 2022-2024 data, NOT from 2025 data. This ensures congestion percentages are consistent between training and testing. WHY USE TRAINING MAX FOR TESTING? • If we used 2025's own max, congestion would be ~10% instead of ~27% • The model was trained to predict congestion RELATIVE to training max • Using training max gives apples-to-apples comparison
⚠️ Common Testing Pitfalls & Solutions
┌─────────────────────────────────────────────────────────────────────────────┐ │ PROBLEM │ SOLUTION │ ├────────────────────────────┼─────────────────────────────────────────────────┤ │ "--%" in results table │ get_feature_sequence_for_station returned None │ │ │ → Not enough history (need 24+ hours) │ │ │ → Test dates after Jan 5, 2025 │ ├────────────────────────────┼─────────────────────────────────────────────────┤ │ Predictions too low (~7%) │ Feature scaler not used correctly │ │ │ → Use saved feature_scaler.pkl from training │ │ │ → DON'T manually normalize features │ ├────────────────────────────┼─────────────────────────────────────────────────┤ │ Actual congestion too high │ Using 2025's own max instead of training max │ │ │ → Always use PER_DIRECTION_MAX from training │ │ │ → Pass use_test_max=false in API call │ ├────────────────────────────┼─────────────────────────────────────────────────┤ │ Chart shows no data │ test_results/*.csv files missing/empty │ │ │ → Run auto-tests first │ │ │ → Click "Run Tests" button │ ├────────────────────────────┼─────────────────────────────────────────────────┤ │ 500 error on station-details│ CSV column has strings instead of numbers │ │ │ → pd.to_numeric(df['predicted'], errors='coerce')│ └────────────────────────────┴─────────────────────────────────────────────────┘
